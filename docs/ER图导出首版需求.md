# DBScribe 自动推断表关系与 ER 图导出首版需求

## 目标与输入

用户连接关系型数据库或 MongoDB，勾选表或集合后，DBScribe 自动发现字段之间有依据的关联，输出可离线查看的 SVG。首次使用无需配置项目词典、提供应用源码或预先标注关系。

推断依据来自当前连接可读取的结构元数据，包括表、字段、类型、键、约束和注释。支持相应方言且权限允许时，可以利用库中已有的视图定义。缺少某类元数据时，系统只使用实际读到的依据。

同样的结构证据在不同项目中应得到一致的裁决。业务库和应用源码可供研发独立复核结果，运行时无需访问它们背后的业务代码。某个库里确实存在一条关系，只能说明这条关系在该库成立；要把发现推广为产品规则，还需说明它依赖的通用证据，以及证据不足时如何暂缓连线。

## 一条线表达什么

一条关系由来源表、有序来源字段、目标表、对应目标键及业务角色构成，箭头从引用方指向被引用方。复合引用保留完整字段配对。同两张表之间的不同角色可以各有一条线。只有约束足以说明基数时，才标注基数。

图中区分**数据库外键、系统推断、人工确认、视图查询关联**。系统推断表示现有材料支持这一解释，读者可以查看理由。MongoDB 的查询关联描述指定视图使用的字段连接。它不会标为外键，也不承诺每份文档都能匹配到目标。未能确定目标的业务关系留在候选区。

## MongoDB 集合关系

每个可见基础集合对应一个节点，嵌入文档和数组属于本集合，按字段路径显示。结构元数据足够时，系统可以从验证规则中的 BSON 类型与描述、完整唯一键和业务命名推断集合引用。`ObjectId` 只提供类型信息；缺少声明的 `_id` 保留其键身份，类型记为未知。

若已保存的视图直接以两个真实集合的字段作 `$lookup` 等值连接，图中可展示带视图名称的查询关联。管道改写了字段来源或只在特定条件下成立时，不把它推广为普遍业务关系。分片拓扑下无法确认全局唯一键时，保留查询关联，暂缓依赖唯一键的自动推断。没有可用的验证规则、索引字段或视图线索时仍保留集合节点。打开集合关系列表和导图只读目录，不采样业务文档。

## 系统如何发现关系

系统先在当前数据库或所选 owner 的可见范围内查找候选，再按用户勾选的表生成图。表的显示范围只影响成图，不改变已有证据或候选之间的取舍。

1. **常规命名。** 对表名和字段名作词边界、大小写等归一处理，用实体名称与键的用途寻找候选。完整命名匹配、目标唯一且结构兼容时，可以自动连线。
2. **异名字段的直接引用。** 字段注释明确说明当前引用的目标与键时，可直接定位。可读视图中的字段比较也可提供线索；须能还原真实端点，并得到引用方向、角色及适用条件的支持。
3. **异名字段的业务描述。** 从来源字段描述中识别引用意图、业务对象和键的用途，再从目标表及其键的定义中分别核对。只有这些描述能唯一对应同一个完整业务键，才可自动连线。字面近义或编号类型相同只够用于查找。
4. **项目内的角色约定。** 当前字段明确表达了角色和用途，且同一业务域的其他对象独立记录了该角色所引用的目标键时，可以复用这项约定。必须能指出它来自哪里、为何适用于当前字段，以及有没有与之冲突的材料。

关系型联结表的一列可以同时承担两种职责：与其他列组合起来标识本表的一行，并单独引用另一张表。仅凭复合主键身份不能断定引用。若每个成员的名称和类型都能唯一对应不同实体的完整键，整组结构可以支持常规命名判断。任一成员存在实质冲突时，其他成员也不能借用这项整组依据。

## 哪些结果进入图

无条件推断以完整主键或有效的全表唯一键为目标，两端字段须逐一对应、类型可直接比较。MySQL 的普通唯一索引允许键位可空。若全部键位按相同类型和比较规则以普通等号连接，且都有值，则至多匹配一行。系统可针对这个范围画一条标有“非空等值”的推断线。没有匹配行也符合这条线的含义。

两种推断都需要有关业务指向的正面依据。目标具有唯一索引本身不能决定谁在引用它。对可空唯一键，清晰指向目标的注释、完整无歧义命名，或可定位且有方向依据的普通视图列对，才可能支持自动线。同一线索的多种解析共享出处。适用条件须随预览、离线 SVG 和关系报告一起交付。NULL 安全等值可能让空值匹配多行，不能用它证明普通非空等值引用。

- **自动连线。** 有一条符合上述规则的明确指向，能够排除其他合理目标，且没有与其业务含义或适用范围冲突的材料。
- **保留候选。** 存在竞争目标，或键、角色、业务域、条件、来源独立性仍有影响结论的缺口。系统说明缺少什么，用户可以采纳、排除或保持未决。候选的展示顺序不决定答案。
- **忽略该组合。** 缺乏实体或角色线索，或能确定两端不兼容。已识别但在勾选范围之外的目标单独提示。所有勾选表都保留，包括没有画出关系的表。

## 查看、导出与修正

当字段按同一索引成组出现，而目标业务键的唯一性依赖额外状态或部分索引条件时，系统可以列出条件候选。每条分别显示能配对的字段、目录已声明的目标条件以及尚未绑定的键位。索引条件无法证明应用查询也采用了该条件，因此不能一键采纳为无条件关系。元数据生成的说明仅用于展示，不能作为数据库作者写下的引用依据。

桌面端和 CLI 对相同结构、范围及项目配置使用同一套裁决。桌面预览默认展开全部字段；可逐表或批量收起、展开，收起字段后仍保留关系线。卡片标题只显示完整表名，表注释另起一段。字段名、键标记、类型与字段说明分别排版。桌面导出的离线 SVG 保留当时的显示状态，使用箭头、线型和文字区分关系来源。CLI 默认显示全部字段，可用 `--key-columns` 生成仅含键和关系字段的简图。

用户作出的修正限于当前项目、端点和角色。再次导出时复核其依据；端点、键或相关业务说明发生变化时，提示哪些决定需要重审。数据结构、处理顺序和模块边界见[首版实施方案](ER图导出首版实施方案.md)。

本地裁决使用完整可见目录。交付文件按所选实体投影，汇总图外候选和不属于选区的警告；选区内实体自身的数据库注释保留原文。
