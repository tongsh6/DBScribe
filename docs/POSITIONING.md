# 项目定位

> 这份文档用于对齐「DBScribe 是什么、为谁做、不做什么」，后续功能取舍以它为准。

## 一句话定位

**DBScribe 是跨平台的数据库结构文档工具：GUI 点几下、CLI 一条命令，把数据库结构导出成可交付的文档。**

## 目标用户

**个人开发者 / 小团队。**

典型场景：

| 场景 | 期望 |
| --- | --- |
| 新接手一个项目 | 连上库，导出结构，快速摸清有哪些表、字段含义 |
| 项目交付 / 外包结算 | 附一份数据字典（通常是 Excel）给甲方或运维 |
| 给产品、测试解释结构 | 导出一份可读的文档发过去，而不是截图 |
| 项目文档站 | 用 Markdown/HTML 输出，跟着代码一起维护 |

这类用户的共同点：**不想装一套重型客户端，也不想配复杂的建模工具**——就要一份能交付的结构说明。

## 核心价值

1. **快**：从连接数据库到产出文档，几十秒完成
2. **跨平台**：Windows / macOS / Linux 同一套实现，产物是单文件二进制
3. **多格式可交付**：Excel（最常交付）、Markdown（进文档站）、HTML（直接看）、JSON / XML（二次处理）
4. **可脚本化**：CLI 能进 CI，文档可以随代码自动更新
5. **不丢表**：工作表名超长 / 重名 / 非法字符自动处理，不会因一张表的命名问题导致整份文档导出失败

## 明确不做

以下需求属于其他产品，刻意不在本项目范围内：

| 不做 | 交给谁 |
| --- | --- |
| SQL 编辑器、查询执行、结果集编辑 | DBeaver、DataGrip、Navicat |
| 数据库结构比对 / 同步 / 迁移 | Flyway、Liquibase、专用 diff 工具 |
| 实体类代码生成 | MyBatis Generator、EF Core 脚手架 |
| CHM 导出 | Windows 专有格式，用 HTML 站点替代 |
| 团队协作、权限、在线文档平台 | 当前用户规模不需要，且会显著增加部署复杂度 |

## 与同类工具的差异

| 工具 | 差异点 |
| --- | --- |
| DBeaver | 通用数据库客户端，导出文档只是附属能力；DBScribe 专注文档，输出格式更适合交付 |
| tbls / SchemaSpy | CLI 能力强但无图形界面、配置门槛高；DBScribe 同时提供 GUI 与 CLI |
| 原 SmartSQL | 仅 Windows（WPF）；DBScribe 三平台，且修复了多 Sheet 导出的命名冲突缺陷 |
| Navicat | 商业授权；DBScribe 开源免费 |

## 路线图

围绕「把数据库文档这件事做到最好」，优先级如下：

1. **多数据库支持**：MySQL ✅ → PostgreSQL ✅ → SQLite ✅ → SQL Server ✅ → Oracle ✅
   > 定位是「任意数据库」，只有一个 MySQL 撑不起这个定位
2. **文档质量**：索引信息、外键关系、ER 关系图
   > 「文档」是核心交付物，结构越完整越有用
3. **交付体验**：文档模板、一次导出多个库
4. **CI 集成**：文档随代码提交自动更新

## 功能取舍的判断标准

新增需求时依次自问：

1. 它是否直接服务于「生成更好的数据库文档」？
2. 个人开发者 / 小团队是否真的会用到？
3. 维护成本与收益是否匹配？（引入重依赖、跨平台兼容问题要额外谨慎）

符合前两条、第三条可控的，才进入路线图。
